寫教學應用程式的五個等級

純前端 → +Sheets → +Firebase → +AI（不存）→ +AI+資料庫（全端）

🎯 這集要解決的問題

老師問「我要不要學後端？要不要碰 Firebase？」其實答錯題了。真正的問題是：這個工具需不需要『記住』東西？記給誰看？要不要 AI 幫忙思考？

先問資料要不要存、要不要 AI，再決定爬到第幾階。

不是越高級越好，是剛好夠用最好。多爬一階＝多一份維護成本。

🍽️ 先立比喻（餐廳）

角色餐廳比喻在程式裡
前端餐廳服務生使用者看到、互動的畫面（HTML/CSS/JS）
後端廚房處理資料和指令的地方
資料庫儲藏室 / 冰箱把資料存下來
AI請了一位米其林顧問即時生成、判斷、對話

五個等級＝這間餐廳長大的五個階段。AI 那部分分兩層：L4＝顧問當場問完就走、L5＝顧問講完還把病歷寫進儲藏室。

🪜 五個等級總覽

等級架構一句話資料存哪適合場景
Lv.1純前端算完就忘不存計算器、抽籤、互動教材、模擬動畫
Lv.2前端 + Google Sheets存進你熟的試算表Google 試算表收表單、點名、回饋、成績登錄
Lv.3前端 + Firebase即時、多人、自己更新Firestore即時排行榜、一人一碼派題、多人協作
Lv.4前端 + 後端 + AI安全地用 AI（用完即走）不存（後端只代打 AI）AI 即時問答、即時批改、即時翻譯
Lv.5前端 + 後端 + 資料庫 + AI會思考又會記住Firebase / Sheets ＋ AIAI 批改存成績、AI 家教記錄、學習歷程
L4 → L5 的差別：L4 只是「安全地用一下 AI」，算完不留資料；L5 把 L2/L3 的資料庫接回來，AI 結果會被存下來、能累積。L5 ＝ L4 的 AI ＋ L2/L3 的資料庫。
主線設計（同一主題爬五階）：「課堂問答」線
Lv.1 純前端隨機抽人 → Lv.2 答案寫進試算表 → Lv.3 手機即時搶答＋排行榜 → Lv.4 AI 即時批改（看完即走）→ Lv.5 AI 批改＋存成績與歷程。

🎬 同一個例子爬完五階：「隨堂測驗」

用一份小考，五種長相。每爬一階只多一個能力，觀眾一眼看出差別。這是全集的示範主軸；各等級下方的「示範建議」是其他可替換的例子。

Lv.1 純前端 ——「自我練習版」

  • 做什麼：網頁出 10 題選擇題，學生自己作答，當場顯示對幾題 + 詳解
  • 技術：單一 HTML，題庫寫在前端，作答只在瀏覽器記憶體
  • demo 重點：作答 → 立刻打分 → 看詳解。漂亮、即時、零成本
  • 限制：關掉就忘，老師不知道誰考了、考幾分
  • ➕ 起點

Lv.2 +Google Sheets ——「課後回收版」

  • 做什麼：同一份小考，學生填完按「送出」，座號 + 分數 + 作答寫進 Google 試算表
  • 技術：前端 → GAS → 試算表
  • demo 重點：老師打開試算表，全班成績一覽，能排序、算平均、畫圖
  • 限制：送出後要等幾秒、不即時；很多人同秒送出會卡
  • ➕ 比 L1 多了：把成績存下來（老師有完整紀錄）

Lv.3 +Firebase ——「即時競賽版」

  • 做什麼：同一份小考變即時搶答賽。老師大螢幕一個即時排行榜，學生一送出立刻跳動
  • 技術：前端 → Firestore，onSnapshot 即時同步
  • demo 重點：全班同時作答，老師螢幕即時看到誰交了、誰最快、分數排行，炒熱氣氛
  • 限制：要寫安全規則、個資去識別化
  • ➕ 比 L2 多了：即時、多人（從「課後看」變「當場看」）

Lv.4 +AI（不存）——「AI 即時講解版」

  • 做什麼：小考多了一題問答題 / 簡答題，學生寫一段文字，按「請 AI 批改」，AI 即時判對錯、指出錯在哪、給訂正建議
  • 技術：前端 → Netlify Function（藏 Groq key）→ AI → 回前端，不存
  • demo 重點：開放式答案也能即時批改，不再只能考選擇題
  • 限制：AI 結果看完即走，下次老師看不到歷史；要顧 key / 成本 / 幻覺
  • ➕ 比 L3 多了：AI 會批改開放式答案（但不留紀錄）

Lv.5 +AI+資料庫 ——「AI 學習歷程版」

  • 做什麼：同樣 AI 批改問答題，但批改完把「分數 + AI 回饋 + 原始作答」存進 Firebase。老師端儀表板：每位學生歷次小考、AI 標的弱點、進步曲線
  • 技術：前端 → 後端（藏 key + 打 AI）→ Firebase → 回前端 + 老師儀表板
  • demo 重點：一條龍——學生作答 → AI 批改 → 存檔 → 老師看長期學習歷程與弱點分析
  • 限制：五階之最，key + 規則 + 成本 + 個資全要顧
  • ➕ 比 L4 多了：把 AI 結果存下來＝學習歷程
一句話階梯：L1 自己練 → L2 存成績 → L3 即時比 → L4 AI 批 → L5 AI 批了還記住。每一階只多一個能力。

1️⃣ Lv.1 純前端算完就忘

示範建議

  • 座標獵人 / 隨機抽籤器 / 互動式幾何動畫
  • 一個單一 HTML，響應式，丟 GitHub Pages 或 Netlify 就能用

關鍵提示詞

生成一個單一 HTML 網頁程式，採用響應式設計

優點

  • 門檻最低：一個檔案、不用帳號、不用後端
  • 部署最快：10 秒上線
  • 零成本、零維護
  • 隱私最安全：資料不離開瀏覽器

缺點

  • 關掉就忘，重新整理資料就沒了
  • 無法跨裝置 / 跨人，老師看不到學生做了什麼
  • 無法累積、無法統計
「這工具只是當下算一次、看一次？」→ 留在 Lv.1 就好，別過度工程。

2️⃣ Lv.2 前端 + Google Sheets存進你最熟的試算表

示範建議

  • 學生成績自動登錄系統（EP03）/ 課堂回饋收集 / 線上點名表
  • 架構：前端 HTML → GAS（Google Apps Script）→ Google 試算表

兩種做法

  1. GAS 部署法（EP05）：Canvas 生成 index.html + code.gs，部署成網頁應用程式
  2. Netlify + GAS API 法（EP03）：Netlify 託管前端、GAS 當 API、試算表當資料庫

優點

  • 資料落在老師最熟的試算表：打開就懂、能排序畫圖匯出
  • 免學 Firebase 的規則 / 權限，門檻比 Lv.3 低
  • 免費（Google 額度內）
  • 資料天生「人類可讀」，適合給行政 / 同事看

缺點

  • 不是即時：GAS 有配額與延遲，不適合「秒級多人搶答」
  • 併發弱：很多人同時寫容易卡或撞列
  • GAS 部署對新手仍有貼碼、授權、改存取權幾個坑
  • 規模一大會明顯變慢
「資料量不大、不要求秒級即時、我想自己打開試算表看」→ Lv.2 最舒服。

3️⃣ Lv.3 前端 + Firebase即時 · 多人 · 自己更新

示範建議

  • 分班即時排行榜（EP10 demo 2）/ 一人一碼的教學駕駛艙（EP11）
  • 架構：前端 → Firestore（前端直接讀寫，靠安全規則把關）

殺手鐧

  • onSnapshot 即時同步：學生一答，老師畫面立刻更新（一行 query + 一行 onSnapshot）

優點

  • 真即時：即時排行榜、即時派題、即時看全班進度
  • 併發強：全班同時寫沒問題
  • Firebase Config 可公開（apiKey 設計給前端用，不算機密）
  • 配 Firebase MCP，能用自然語言對 Claude 直接查資料庫

缺點

  • 要學安全規則（Rules）：寫不好＝資料庫對全世界開放（最大的坑）
  • 建專案、連 MCP、部署規則有學習曲線
  • 資料在 Firestore，不像試算表一眼能讀，要另做後台或匯出
  • 要懂配額概念（Realtime DB vs Firestore 計價不同）
  • 個資要去識別化（用座號、token，不要存真名）
「需要多人同時、即時更新、即時統計」→ 才值得爬到 Lv.3。只是收個表單就上 Firebase＝殺雞用牛刀。

4️⃣ Lv.4 前端 + 後端 + AI安全地用 AI · 用完即走

定位：踏進 AI 的最小可用版。後端只做一件事——藏 key、安全代打 AI。沒有資料庫，AI 算完即走。先把「安全用 AI」學會，L5 再把資料庫接回來。

示範建議

  • AI 即時問答 / AI 家教（單次）、即時批改（看完不存）、即時翻譯、當下出一題
  • 本集示範用 Groq 免費額度 API Key（LPU 推論超快、即時感強、免費額度大方）
  • 架構：前端 → 後端代理（藏 key）→ AI API → 回前端（不落地）

Lv.4a 前端直連 API Key沙盒 / 自己用

  • 純前端 + API Key（Canvas 沙盒、EP05）：最快有感
  • 🔴 但 key 會外洩：寫在 HTML/JS 就會下載到每個人的瀏覽器，F12 就看得到
  • 只適合自己用 / 沙盒分享，絕不能公開上線

Lv.4b 後端代理 API Key正式做法 · 本集主軸

用 Netlify Functions 當後端藏 key（你 EP03 已在用 Netlify，門檻最低、不用碰 Firebase Functions）。

❌ 純前端：key 寫在前端 → 下載到瀏覽器 → F12 看得到 → 外洩
✅ Netlify Functions：key 存 Netlify 環境變數 → 跑在伺服器端 → 瀏覽器看不到

流程

  1. API Key 存進 Netlify 環境變數（Site settings → Environment variables）—— 不寫進程式碼、不進 git、不到前端
  2. 前端只呼叫自己的端點 /.netlify/functions/ask-ai
  3. function 在伺服器端讀 process.env.GROQ_API_KEY → 打 Groq API → 回結果

最小範例

// netlify/functions/ask-ai.js  ← 跑在伺服器端
export default async (req) => {
  const { prompt } = await req.json();
  const r = await fetch("https://api.groq.com/openai/v1/chat/completions", {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${process.env.GROQ_API_KEY}`, // key 只在這裡
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      model: "llama-3.3-70b-versatile",
      messages: [{ role: "user", content: prompt }]
    })
  });
  const data = await r.json();
  return Response.json({ answer: data.choices[0].message.content });
};

前端只 fetch('/.netlify/functions/ask-ai', {...})，看不到 key。

「安全」要分兩層講清楚
風險純前端放 keyNetlify Functions
Key 被偷走（永久損失）🔴 會✅ 不會
端點被陌生人狂打、燒額度🔴 會⚠️ 仍可能
Netlify Functions 解決「key 外洩」，但端點是公開的。課堂建議再加：①來源檢查（只接受自己網站 origin）②簡單通行碼 / token（呼應 EP11 一人一碼）。Groq 免費額度本身就是天花板，燒完即停，風險可控。

🤖 順帶講：AI 功能的種類觀眾最容易搞混

類型全名做什麼教育場景Groq
LLM / Chat文字生成與理解批改、出題、對話、翻譯、摘要AI 家教、自動出題、作文回饋✅ Llama 等
STT語音轉文字聲音 → 字上課錄音轉字幕、口說評量✅ Whisper
TTS文字轉語音字 → 聲音聽力教材、朗讀、無障礙✅ PlayAI TTS
OCR / Vision影像辨識 / 多模態圖片、手寫的字讀出來拍課本 / 手寫作業數位化✅ vision 模型
  • STT vs TTS 方向相反：STT 是「耳朵」（聲→字），TTS 是「嘴巴」（字→聲）
  • OCR 現多被 vision LLM 取代：傳統 OCR 只認字，vision 模型能「認字＋理解」（看懂手寫算式、判對錯）

優點

  • 質變不是量變：從「存資料」升級到「理解資料、生成內容」
  • 開放式答案也能批改、給回饋、對話
  • 門檻比想像低：不用碰資料庫，一個 Netlify Function 就踏進 AI
  • 最有未來感，最能打動觀眾

缺點

  • 🔴 API Key 安全是頭號風險：純前端放 key＝把帳號密碼貼在網頁上 → 用 Lv.4b 後端代理解決
  • 要花錢 / 撞額度：付費 API 按量計費要設上限；Groq 免費版是「每分鐘請求數」上限，全班同時打可能撞 rate limit
  • 會幻覺 / 不穩定：批改結果要留人工覆核
  • ❌ 結果不留下：用完即走，無法累積、無法追蹤（要這個 → 上 Lv.5）
「只要當下用一下 AI、不需要把結果記錄下來」→ Lv.4 就夠了。

5️⃣ Lv.5 前端 + 後端 + 資料庫 + AI會思考又會記住 · 完整全端

定位：集大成。把 L4 的 AI ＋ L2/L3 的資料庫 合體。AI 的結果會存下來、能累積、能追蹤學習歷程——真正完整的教學系統。

示範建議

  • 數學作業 AI 批改 → 成績存進 Firebase（math-homework）
  • AI 家教 + 記錄對話歷程、學習歷程累積分析、一人一碼 + AI（接 EP11）
  • 架構：前端 → 後端（藏 key + 打 AI）→ 資料庫（Firebase / Sheets）→ 回前端

威力組合：一條龍 demo（最炸）

拍手寫作業（OCR / Vision 讀圖）
   → 讀成文字
   → LLM 批改、給回饋
   → 把成績與回饋「存進資料庫」（這步是 L5 比 L4 多的）
   → TTS 把回饋念出來

「存進資料庫」就是 L4 → L5 的關鍵跳躍：從「批完就忘」變成「批完留底、能查歷程」。

優點

  • 會記住：AI 的判斷、學生的歷程都留得下來
  • 能累積、能追蹤成長，可做學習歷程、長期分析
  • 最完整：互動 + 即時 + AI + 資料，一個系統全包

缺點

  • 🔴 工程量最大：前端 + 後端 + AI + 資料庫，四件事一起顧（五階之最）
  • 🔴 個資合規最關鍵：AI ×「存學生資料」同時發生，去識別化、同意、保存期限都要想清楚（呼應 EP10 洩漏教訓）
  • 多重成本與風險疊加：key 安全（L4）＋ 資料庫規則（L3）＋ AI 額度 ＋ 個資
  • 出錯點最多，最需要人工覆核與監控
「需要 AI 思考 + 把結果留下來變學習歷程」→ 才值得爬到 Lv.5。一旦到這階，key 安全 + 資料庫規則 + 成本 + 個資四件事一起扛——爬越高、責任越大。

🤔 對這個分級的建議與可改進處

✅ 這個分級很好的地方

  1. 對應真實能力階梯：每一階剛好多解一個問題（不存→存→即時→用 AI→記住 AI），邏輯乾淨。
  2. L4/L5 拆得好：先單獨學「安全用 AI」（L4），再學「AI ＋ 資料庫」（L5），避免新手一次扛太多。
  3. 跟既有素材完美咬合：EP05 / EP03 / EP09.5+EP11 / Groq / math-homework，把散落集數串成主線。
  4. 「剛好夠用」的價值觀適合老師——破解「我是不是該學更難的」焦慮。

🔧 建議補強

  1. 加一個決策樹開場：要存資料嗎？→否 Lv.1 / 是→要即時多人嗎？→否 Lv.2 / 是 Lv.3。要用 AI 嗎？→要→AI 結果要存下來嗎？→否 Lv.4 / 是 Lv.5。觀眾帶走「怎麼選」。
  2. 講清楚 L4 不是「退步」：L4 沒資料庫會被誤會比 L3 低。明講：L1→L3 是「資料軸」，L4→L5 是「AI 軸」，L5 是兩軸合體。
  3. Lv.2 與 Lv.3 是岔路、不是純線性升級：要「人類可讀＋我熟」選 Sheets；要「即時多人」選 Firebase。避免盲目追高級。
  4. 同一主題貫穿五階（課堂問答線），觀眾看「差別」才具體（沿用 EP10 手法）。
  5. 安全與責任獨立成片尾一段：L3 安全規則、L4 API Key、L5 個資，呼應 EP10 的 Supabase PAT 洩漏教訓——爬越高、責任越大。
